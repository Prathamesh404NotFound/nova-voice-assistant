# Round 35: voice-controlled settings

## Goal
Let the user change Nova's settings by voice, gated through the existing
permission framework:
- "set my personality to playful" / "be more concise" / "make Nova warm" →
  `settings:set-personality`
- "turn on private mode" / "go private" / "disable private mode" →
  `settings:set-private-mode`
- "turn on developer mode" / "exit developer mode" → `settings:set-developer-mode`

## Classification
Settings change machine behavior and affect what later actions will (or won't)
be allowed — Private Mode ON blocks every network call. That is a SENSITIVE
change, so all three actions are **Level 3 (SENSITIVE)**: modal Confirm,
reversible by undoing to the previous value. Personality is arguably lower
risk, but it changes identity wording system-wide and is still reversible —
keep it Level 2 (REVERSIBLE) so it gets the faster toast treatment.
Decision: personality L2 REVERSIBLE; private/developer mode L3 SENSITIVE with
reversible() so "Undo last action" restores the previous state.

## Wording design (additive)
- Personality: "Okay — I'm playful now. Every acknowledgement gets a little
  more mischief." — repeats chosen personality token verbatim.
- Private ON: "Private mode is on. Nothing I do leaves this machine now,
  and you'll see the lock badge."
- Private OFF: "Private mode is off — I can reach my models again."
- Developer ON/OFF analogous.
- Refusal: unknown personality → "I only know four personalities: concise,
  professional, warm, and playful." (planning error, plain language).

## Risk classification sanity (framework)
- L2 toast personality: reversible, no data/network impact.
- L3 modal for private/developer: behavior-changing toggle affecting what
  future actions may do = SENSITIVE per Round-1 rules ("modify settings").
