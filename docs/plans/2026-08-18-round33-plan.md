# Round 33: Natural language note search (upgrade)

## Why
Notes got keyword search in Stage 7 ("what did I note about dentist") — exact-ish substring keyword matching.
Tasks got fuzzy ranked search in R30. Notes are overdue for the same treatment: users ask for a topic, not a literal
word. "what did I note about the dog" should match a note "my golden retriever's vet visit".

## Design
New action `notes:search-notes` already exists for exact keyword. R33 adds a RANKED fuzzy variant under the SAME
action family: extend the planner with new phrases that clearly express topical search, e.g.
"find notes about X", "what did I write about X" (existing), plus NEW shapes: "search my notes for X" (exists —
keep exact), but add topical signals: "find notes on", "find my notes about", "note about".
Actually simpler & cleaner: upgrade the search scoring itself for ALL note-search phrasings — but existing
`notes:search-notes` behavior (plain keyword echo) must stay identical (additive guarantee).

Decision: ADD a NEW action `notes:topic-search-notes` for topical phrasings, keeping the existing keyword action
untouched — zero risk to Stage 7 behavior:
- Planner: new RE_TOPIC_NOTES phrases: "what did I write about X", "what have I noted on X",
  "find notes about/on X", "any notes about X", "notes about X". Keep "what did I note about X" in the OLD
  action (existing behavior).
- Scoring: token matcher like R30 task search — whole-word 10 pts, substring 5, stop-token strip, tiebreak
  most-recent-first, cap 10, honest "No notes match 'X'." empty result.
- Dispatcher: label matches inline with a recency tag ("… (3 days ago)"), cap 5 reads with tail.
- L1 SAFE read-only. Zero network. Additive.
- Harness ~50 tests: routing positives+negatives (no collision with keyword search, task search, kb), scoring
  ladder, recency tiebreak, cap, wording all personalities, additive/no-outbound guarantees.

Implementation files:
1. src/main/notes/plan.js — RE_TOPIC_NOTES regex, route before RE_SEARCH_NOTES (topic intent takes the ranked
   path; old keyword phrases stay in RE_SEARCH_NOTES).
2. src/main/notes/actions.js — register notes:topic-search-notes L1 SAFE.
3. src/main/notes/store.js — none (reuse store.all().notes — note shape {id, text, createdAt, updatedAt}).
4. src/main/notes/dispatch-personal.js — topicSearchNotes(notes, subject) pure scorer + formatter notesTopicText.
5. src/main/notes/dispatch.js — case notes:topic-search-notes; destructure.
6. src/main/test-topic-search-notes.js — harness.
7. wire: add-test-script.py test:topic-search-notes; .gitignore entry; README update; chain → 32 suites.

## Gotchas remembered
- Top-level await flips ESM in CJS; ALL await must live inside async IIFE.
- Number(isoString) === NaN — never guard ISO strings with Number().
- Ternary precedence: `cond ? a : b / 60_000` binds / only to b.
- setNowForTesting: plan.js owns it; dispatch.js re-exports.
- registerAction's reverse() is visible only via getAction().
- Notes content never leaves machine — search actions must remain zero-outbound.
